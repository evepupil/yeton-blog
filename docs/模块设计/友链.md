## 职责与边界

友链模块负责校验并展示 `data/friends.json`，提供中英文静态页面、友链申请、中英文文案、站点外链、头像失败回退、导航入口、SEO 和响应式布局。申请只写入 Notion 的“待审核”记录；管理员审核、头像下载和公开列表生成仍由 Notion 同步模块负责。

## 结构与数据流

| 路径                                           | 用途                                   |
| ---------------------------------------------- | -------------------------------------- |
| `lib/friends/schema.ts`                        | 友链文件和单条友链的公共 Zod 规则      |
| `lib/friends/repository.ts`                    | 构建时读取并校验 `data/friends.json`   |
| `lib/friends/application.ts`                   | 申请字段校验和 Notion 页面字段映射     |
| `lib/friends/rate-limit.ts`                    | 友链申请的独立 D1 限流命名空间         |
| `lib/rate-limit.ts`                            | AI 与友链共用的 D1 原子限流实现        |
| `features/friends/friends-page.tsx`            | 页面标题、数量、列表和空状态           |
| `features/friends/friend-card.tsx`             | HeroUI 友链卡片与外部链接              |
| `features/friends/friend-avatar.tsx`           | 头像加载失败后的首字母回退             |
| `features/friends/friend-link-application.tsx` | 申请入口、弹窗和提交状态               |
| `features/friends/friend-link-client.ts`       | 同源申请接口客户端                     |
| `features/friends/friends.css`                 | 桌面、手机和明暗主题样式               |
| `functions/api/submit-friend-link.ts`          | Pages Function、来源校验和 Notion 写入 |
| `app/(zh)/links/page.tsx`                      | 中文静态路由与元数据                   |
| `app/(en)/en/links/page.tsx`                   | 英文静态路由与元数据                   |
| `tests/unit/friends.test.ts`                   | 文件结构和 URL 安全规则                |
| `tests/e2e/home.spec.ts`                       | 页面、外链、回退和语言切换             |

申请表单通过同源 `POST /api/submit-friend-link` 提交名称、HTTPS 站点地址、描述和可选头像地址。Pages Function 先限制来源、请求体大小、字段长度和 URL 协议，再使用运行时 Secret 调用 Notion REST API，创建状态为“待审核”的页面；D1 记录按 IP 哈希后的用户和全站次数。同步脚本随后下载审核通过的头像，再把站点名称、简介、HTTPS 地址和本地头像路径写入 JSON。Next.js 构建时通过 `getFriendLinks` 解析 JSON；字段不合法会直接让构建失败。浏览器永远不会拿到 Notion Token。

## 关键决策

1. 页面使用 `/links/` 与 `/en/links/`，和站内其他栏目保持同一套语言前缀与尾斜杠规则。
2. 外部站点在新标签页打开，并设置 `rel="noreferrer"`；站内语言切换和导航继续留在当前标签页。
3. 头像路径只接受 `public/` 下的绝对站内路径。同步阶段把远程头像下载到本地，减少第三方站点故障和隐私泄露对页面的影响。
4. 浏览器仍可能遇到文件删除、损坏或缓存异常。`FriendAvatar` 监听图片错误，失败后显示站名首字母，卡片尺寸保持不变。
5. 友链卡片使用 HeroUI Card，整卡只有一个外部链接；没有嵌套链接，键盘焦点和鼠标悬停状态一致。
6. 申请接口使用原生 Notion REST `fetch`，避免把 Node SDK 和服务端凭据带入浏览器构建产物。
7. 申请状态只由 Notion 管理员推进到“已通过”；接口不直接修改 `data/friends.json`，公开列表仍通过 Git 同步，保留审计和回滚能力。
8. 申请使用 `friend-links:` 限流命名空间复用现有 D1 表，和 AI 搜索计数隔离；隐藏蜜罐字段只作为低成本机器人过滤。

## 当前实现

中文和英文页面共用 `FriendsPage`。页面顶部沿用全站 `PageIntro`，下面提供申请入口和 HeroUI 弹窗；列表在桌面使用两列、手机使用单列；卡片显示头像、站名、域名、两行简介和外链图标。申请成功后只显示“等待审核”，不会乐观地把未审核站点加入列表。

友链页已加入桌面导航、移动菜单、页脚和 sitemap。静态产物检查要求中英文页面都存在，部署冒烟会访问中文友链页。

## 验证方式

- `tests/unit/friends.test.ts` 验证安全 URL、本地头像路径和严格字段结构。
- `tests/unit/friend-link-application.test.ts` 验证申请字段、URL 凭据限制和 Notion 字段映射。
- `tests/unit/friend-link-api.test.ts` 验证同源校验、服务配置缺失、限流、Notion 写入和错误边界。
- `tests/unit/navigation.test.ts` 验证友链导航、激活状态和语言切换。
- `tests/unit/seo.test.ts` 验证中英文友链地址进入 sitemap。
- Playwright 拦截真实头像请求，确认首字母回退可见、外链属性正确、语言切换进入英文页面。
- 浏览器视觉检查覆盖桌面 `1440x1000` 和手机 `390x844`，检查裁切、换行、卡片高度和控制台错误。

## 当前限制与待扩展项

- Pages Production 和 Preview 必须分别配置 `NOTION_TOKEN`、`NOTION_FRIEND_LINK_DATABASE_ID`，否则申请接口会安全返回 `503`，静态友链页面仍可访问。
- 当前没有管理员后台；审核仍在 Notion 中完成，公开列表要等 GitHub Action 同步和 Pages 构建。
- 当前只用同源校验、D1 限流和蜜罐字段防滥用；若公开流量明显增加，再接入 Turnstile 或更细的站点级黑名单。
- 页面不主动检查外部站点是否在线，失效链接由 Notion 审核流程处理。
